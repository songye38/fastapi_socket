### ✅ 1단계: 웹소켓 기초 맛보기 (완료)

- **목표:** 하나의 큰 방에서 새로고침 없이 실시간으로 메시지가 오가는 기본 메커니즘 확인하기.
- **할 일:** 싱글 리스트(`active_connections`)를 활용한 초간단 서버 띄우기, 가상환경 세팅 및 Uvicorn 웹소켓 에러 조치.
- **결과:** 로컬에서 브라우저 2개 켜고 대화 주고받기 성공!

### 2단계: 주소창 조작으로 방 분리하기 (완료)

- **목표:** 전 세계 사람들이 한 방에 모이는 게 아니라, `apple` 방, `banana` 방처럼 대화방을 독립시키기.
- **할 일:** * 파이썬 **딕셔너리(`dict`)** 구조를 도입하여 `{ "방이름": [연결된 소켓들] }` 형태로 데이터 구조 업그레이드.
    - 엔드포인트 주소를 `/ws`에서 `/ws/{room_id}`로 변경.
    - 브라우저에서 `?room=방이름`으로 접속하면 자동으로 해당 방 소켓에 조인되도록 연동.

### ✅  3단계: 웹 환경에 내 서버 올리기 (Railway 배포)

- **목표:** `localhost`가 아니라, 인터넷이 연결된 곳이라면 전 세계 누구든 내 채팅방에 접속할 수 있게 만들기.
- **할 일:** * 내 가상환경의 패키지 목록을 추출한 `requirements.txt` 생성.
    - Railway에 실행 명령을 내릴 `Procfile` 생성.
    - 코드를 GitHub에 푸시하고 Railway와 연동하여 실제 `https://...` 및 `wss://` 도메인 받아내기.

### 4단계: 진짜 '채팅 서비스'처럼 화면 고도화하기 (선택/추가 단계)

- **목표:** 주소창을 지저분하게 바꾸지 않고, 화면 안에서 직접 방을 만들고 유저 이름을 입력해서 대화하기.
- **할 일:**
    - **유저 닉네임 입력창**을 만들어서 "익명 유저"가 아니라 "송이: 안녕!" 처럼 이름이 뜨게 만들기.
    - 화면에 **방 목록 리스트**나 **방 만들기 버튼**을 추가해서 일반적인 채팅 서비스 모양새 갖추기.

### 5단계: 영구 저장소 연동 (DB 붙이기)

- **목표:** 서버를 껐다 켜도, 혹은 새로고침을 해도 예전 대화 기록이 유지되게 만들기.
- **할 일:**
    - 지금은 메모리(딕셔너리)에만 대화가 머물러서 서버가 꺼지면 다 날아감.
    - 메시지가 발생할 때마다 데이터베이스(SQLite 또는 PostgreSQL)에 저장하는 로직 추가.
    - 방에 처음 입장할 때, 기존 REST API처럼 DB에서 과거 메시지 20개를 긁어와 화면에 먼저 그려주는 기능 구현.
